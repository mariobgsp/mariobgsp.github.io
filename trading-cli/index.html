[ 01 ] WHAT IT IS

In plain words

It screens roughly 900 IDX/IHSG tickers each morning against the Minervini Trend Template (8 checks) plus a VCP contraction score, then plans the entry zone, stop and targets for the ones that qualify.

Each pick is also backtested across 18 strategies with real IDX fees and slippage, tagged with the market regime at entry, and re-checked walk-forward out-of-sample so a threshold is only kept when it survives unseen data.

It is for a swing trader or a screening agent that wants machine-readable output and an explicit no-trade answer instead of a forced recommendation.

[ 02 ] PURPOSE

Why it exists

Most screeners answer with a list and no accounting for whether the list makes money. This one answers with a plan and an honest no-trade: roughly 900 IDX tickers screened each morning, then every qualifying pick backtested against 18 strategies with real fees and slippage, tagged with the market regime at entry and re-checked walk-forward out-of-sample.

The output is machine-readable JSON on purpose - picks, near_miss, leaderboard, regime_pooled, wf_regime - so a swing trader or an agent can run it before the open and sit out when the evidence is thin instead of forcing a recommendation.

[ 03 ] TECH STACK

What it is built on

Python 3.11+ and pandas
The whole tool is one CLI (trading_cli/cli.py); indicators and scan math are pandas over daily bars - no server, no API keys, no database to run.
yfinance + SQLite
The data path: a throttled 4-thread fetch with rate-limit backoff over a 12h-TTL WAL cache in the XDG cache directory, with stale-while-revalidate.
Minervini Trend Template + VCP
The screen itself: 8 trend checks plus a volatility-contraction score, with relative strength measured against ^JKSE before any candidate is planned.
Walk-forward validation
Rolling train-252 / step-60 windows: a threshold is kept only when it survives unseen data, which is why the README reports roughly 50% pooled win rate instead of a 70% sleeve.
Expectancy + Wilson interval
Ranking is by expectancy p*avgWin + (1-p)*avgLoss and a 95% Wilson bound, not raw win rate, so a high win rate with 0.5R losers cannot top the leaderboard.

[ 04 ] STRUCTURE

Where the code lives

  • trading_cli/cli.py - the whole surface (the trading-cli script in pyproject.toml): flags, scan, expectancy ranking, qualifiers split from near_miss, JSON out.
  • trading_cli/scan.py, minervini.py, data.py, cache.py - universe fetch and throttling, trend template, VCP score and relative strength over the SQLite cache.
  • trading_cli/backtest.py + regime.py - the 18-entry STRATS table, next-open fills with fees and slippage, and the regime tags each trade carries.
  • trading_cli/validate.py + tune.py - walk-forward out-of-sample replay and the VCP threshold grid under the same gate.
  • trading_cli/entry.py + ml_filter.py - buy zone, tightest stop and T1/T2/T3 targets, plus the pooled-n and leakage guards that keep future ML work honest.

[ 05 ] ARCHITECTURE

How it works

  • One pass produces the answer: scan the universe, gate on regime (ADTV, ATR14, IHSG stage, CMF), rank survivors by expectancy, then split them into qualifiers and near_miss.
  • Every pick carries its evidence: the strategies that backtested it, the pooled win rate with a Wilson bound, and the regime tag at entry.
  • Thresholds are earned rather than chosen: validate.py replays strategies on rolling windows and tune.py grids VCP thresholds under the same out-of-sample gate.
  • The entry plan is derived from the pivot: the 20-day high becomes the buy zone, and the tightest of the 20-day low, close minus 2 ATR or -8% becomes the stop.
  • Data is daily and best-effort: yfinance with throttle and backoff, so coverage is only as good as that feed - reported in the README rather than hidden.

[ 07 ] QUICKSTART

See it work

  1. trading-cli --scan-only --limit 50 --period 1y — the fastest run: a qualifier table plus the NEAR MISS block, a few seconds when cached. --scan-only skips the backtest stages, so the 70% HUNT and leaderboard blocks only appear on a full run.
  2. trading-cli --ticker BBCA — one-ticker deep dive with the Trend Template checks, VCP score, entry plan and per-strategy backtest stats.
  3. trading-cli --json > picks.json then jq '.leaderboard' — the machine-readable expectancy leaderboard the agent workflow parses.
  4. trading-cli --period 2y --validate — per-window out-of-sample results for the top strategies plus the pooled wf_regime block.
  5. trading-cli --doctor — confirms the data path with a live probe of ^JKSE plus sample tickers and reports cache size.

[ 09 ] TRADEOFFS

What it does not do

  1. The README's own honesty section states there is no proven 70% win-rate sleeve on daily yfinance OHLCV alone: every higher-R and divergence candidate failed both the pooled Wilson gate and the 2y walk-forward gate, and the measured ceiling is about 50% pooled win.
  2. Institutional and broker-flow filters are not built: broker concentration or a foreign net-buy streak needs an idx.co.id scrape the README calls fragile, so it stays deferred behind ml_filter.gate_pooled_n(need=100), and there is no intraday VWAP because the data path is daily yfinance only.
  3. Regime gating is deliberately soft (a -20 combo demote, not a hard veto) with fixed, untuned thresholds, so Stage 4 tape still produces candidates; changing it is gated on out-of-sample evidence at n>=100.
  4. Everything depends on Yahoo Finance daily data through trading_cli/data.py, which throttles and needs --workers 4 when it answers 401/429, so coverage and quality are only as good as that feed.
