[ 01 ] WHAT IT IS

In plain words

t-notes is a single-user notes app and a kanban board in one, with all data kept in your own browser - nothing is sent to a server, and there is no account or sync service.

A note can also be pinned to a board list, and then the same item shows up as a card in both views, so edits stay in sync. Cards carry checklists with progress, due dates, comments, labels, tags and image attachments.

It is for people who want Trello's core without the cloud: run it from static files on any OS with a browser, or on Windows as a small Go exe or a Tauri desktop app.

An optional AI assistant (bring your own key) can summarize, draft checklists and suggest ideas; the key stays local and is never exported.

[ 02 ] PURPOSE

Why it exists

t-notes is the answer to using a board and a notes app for things that should never leave the laptop: no account, no sync service, no build step and no framework. All data stays in browser localStorage, and the board and the notes are one system - a note pinned to a list renders as a card in both views.

It also exists to show how small that can be: the entire UI is three static files, the Windows build is a 9.7 MiB Go exe that embeds them, and the Tauri shell adds one Rust command for large-corpus search.

[ 03 ] TECH STACK

What it is built on

Vanilla HTML, CSS and JavaScript
web/index.html, styles.css and app.js are the entire UI - no framework, no bundler, no npm install; content-visibility: auto keeps long lists cheap and the three themes are plain CSS.
localStorage
The only datastore: all state lives under the key t-notes-v1 and is written on every mutation, so there is no API client and no server-side session.
Go with //go:embed
main.go embeds web/ and serves it from a local net/http server, opens the default browser, and self-installs or uninstalls from the same binary.
Tauri v2 + Rust
The desktop shell: one Rust command (match_notes) for batch substring search with a JS fallback, and an NSIS installer with a launch-on-login plugin.
Playwright
e2e/t-notes.spec.js (15 tests) runs against system Chromium with a mocked AI endpoint; build-windows.sh cross-compiles the Windows exe and setup exe from Linux.

[ 04 ] STRUCTURE

Where the code lives

  • web/ - the entire front end: index.html, styles.css, app.js and logo.svg, with const K = t-notes-v1 at the top of app.js as the storage key for all state.
  • main.go - the Go host: //go:embed web/, the local net/http server, browser launch, and the setup/--install and --uninstall paths.
  • src-tauri/ - the desktop shell: src/main.rs exposes match_notes, and tauri.conf.json sets frontendDist to ../web and bundles the NSIS installer with tauri-plugin-autostart.
  • e2e/t-notes.spec.js - the Playwright suite, run against system Chromium with a mocked AI endpoint.
  • build-windows.sh + go.mod - cross-compile the Windows exe and setup exe from Linux.

[ 05 ] ARCHITECTURE

How it works

  • One store, two views: notes pinned to a board list render as cards, so the board and the notes view are the same objects and an edit in either is the same write.
  • Two host paths share one front end: the Go exe acts as a browser launcher (with an /api/startup fallback for the power toggle) and the Tauri app opens its own window and installer.
  • State is local-first by construction: no sync layer, no account and no multi-device story - the only optional network call is the bring-your-own-key AI request.
  • The AI assistant keeps the key in the browser and never exports it; summaries, checklists, rewrites and ideas all run against the URL and key the user supplies.
  • Long lists stay cheap by capping what is rendered (a 50-item window) and letting content-visibility skip off-screen work.

[ 06 ] INSTALL

Set it up

cd t-notes/web
python3 -m http.server 8000   # open http://localhost:8000 (Ctrl-C to stop)
cd ..   # the two optional commands below run from the repo root
sh build-windows.sh   # optional: dist/t-notes.exe + dist/t-notes-setup.exe from Linux (needs Go)
npm install && npx tauri dev   # optional: Tauri desktop app on Linux (needs Rust)

[ 07 ] QUICKSTART

See it work

  1. Run python3 -m http.server 8000 inside t-notes/web and open http://localhost:8000 - the Notes and board UI loads with no build step.
  2. Click + New note, type a title first, and save: the note appears in the Notes list and a toast confirms every action.
  3. Create a column with the New list… box, then add a card and drag it between columns to see the board update.
  4. Pin a note to a board list so it renders as a card too, then click it to open the detail dialog (body, checklist + progress, list picker, image attachments).
  5. Toggle the theme button to cycle light / dark / midnight - the choice persists across reloads.
  6. Use ⤓ to export all data as JSON and ⤒ to restore it, or the ? button for the in-app guide.

[ 09 ] TRADEOFFS

What it does not do

  1. The Windows installer is unsigned: SmartScreen shows an "Unknown publisher" warning and the user must click More info → Run anyway (signing needs a paid cert, skipped for now).
  2. There is no auto-updater yet - new versions are manual downloads from GitHub Releases.
  3. The first install needs internet once for the WebView2 bootstrapper (nearly all Windows 10/11 PCs already have WebView2).
  4. It is single-user and local-only: data lives in browser localStorage, so there is no sync, no sharing and no multi-device story.
