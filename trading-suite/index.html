[ 01 ] WHAT IT IS

In plain words

A self-hosted desk for the Indonesian stock market (IDX). It pulls quotes, history, foreign flow and broker activity from public feeds, caches them, and turns them into five screens: an overview, a charting page with foreign-flow bars, a streaming screener, a per-ticker profiler, and calculators.

It is for one person or a small team who wants their own copy of the market data rather than a subscription, and who is happy to run a backend and a front end on their own machine.

Nothing is stored in a company cloud: quotes live in a local SQLite WAL cache under backend/data/cache.db, and the only outbound calls are to the public data sources.

[ 02 ] PURPOSE

Why it exists

This repo exists to answer one question once a session: which Indonesian stocks should be bought at the next open, and why. It is a self-hosted desk - your own FastAPI backend, your own cached copy of the market data - instead of another market-data subscription.

The strongest feature is bandarmology, Indonesian broker-flow analysis: phase, intent radar and flow metrics computed from broker activity, with a FIFO portfolio engine and a backtest surface behind the same API, so a number on screen can be traced back to the code that produced it.

[ 03 ] TECH STACK

What it is built on

Python + FastAPI
The backend: one router per domain (market, screener, validator, intel, analysis, regime, backtest, portfolio, summary, alerts, sentiment) with the analysis kept one level up in service modules.
SQLite in WAL mode
The cache seam: per-feed TTLs with stale-while-revalidate in backend/data/cache.db, so a screen refresh does not hammer the public feeds.
Server-Sent Events
The screener streams results from GET /api/screener/scan/stream and the client mirrors the same cache policy in src/lib/cache.ts (memory + sessionStorage).
Next.js 16 + React + TypeScript
The five UI routes (overview, markets, screener, profiler, calculators) after a lean pass from 22 app routes; the nav is generated from one source in src/lib/apps.ts.
curl_cffi + yfinance
The data path: an IDX summary endpoint and .JK history - cached copies of third-party feeds, not an exchange-grade tick store, and the repo says so.

[ 04 ] STRUCTURE

Where the code lives

  • backend/app/main.py - wires the routers; backend/app/routers/ holds one router per domain and the services live one level up in backend/app/*.py.
  • backend/app/screener.py, idx.py, cache.py, db.py - the scan path: the suspended-ticker filter runs before the ThreadPool fan-out, then results stream over SSE from the SQLite WAL cache.
  • backend/app/validator.py - BandarmologyAnalyzer (phase, intent radar, flow metrics) behind GET /api/validator/{ticker} and inside the profiler page.
  • backend/app/_fifo.py + portfolio.py - the FIFO P/L engine and its JSON load/save; backend/app/backtest.py + routers/analysis.py - the pattern backtests. Both are API-only: next.config.ts redirects /portfolio and /backtest to /profiler.
  • frontend src/app/{overview,markets,screener,profiler,calculators} with src/lib/apps.ts as the single nav source, and backend/data/cache.db as the only datastore.

[ 05 ] ARCHITECTURE

How it works

  • Caching is the seam that makes it cheap: per-feed TTLs in a SQLite WAL file with stale-while-revalidate and _spawn_refresh dedupe, mirrored in the browser by src/lib/cache.ts.
  • A scan is filtered before it is fetched: the suspended-ticker filter runs in idx.py before the ThreadPool fans out, so excluded names never reach a feed.
  • The API is the product surface: routers stay thin and the analysis lives in service modules, so the profiler page, the validator endpoint and the backtest endpoint all read the same engine.
  • Nothing is stored in a company cloud: quotes live in backend/data/cache.db and the only outbound calls are to the public data sources.
  • AI summaries are no longer a feature: backend/app/ai.py is an explicit no-op stub that returns None and nothing imports it, so every caller falls back to deterministic text.

[ 07 ] QUICKSTART

See it work

  1. Start both halves with the runner from the repo root: chmod +x ./trading-suite && ./trading-suite run (backend on :8000, front end on :3000).
  2. Open http://localhost:3000 - the launcher shows exactly five cards: Overview, Markets, Screener, Profiler, Calculators.
  3. Go to /screener: the scan streams in over SSE rather than waiting for one big payload.
  4. Open /profiler?ticker=BBCA - one screen showing quote, candles, beta, regime, the bandarmology phase, the intent radar, the broker panel and an entry plan.
  5. Check the backend directly at http://127.0.0.1:8000/api/health, and browse the auto-generated API at http://127.0.0.1:8000/docs.

[ 09 ] TRADEOFFS

What it does not do

  1. AI-generated summaries are not a working feature any more: backend/app/ai.py is an explicit no-op stub ('AI section has been dismantled'), it returns None and nothing imports it, so every caller falls back to deterministic text - the README's OPENCODE_GO_API_KEY row is stale and was left out of the claims above.
  2. FIFO portfolio tracking and pattern backtesting are backend-only: next.config.ts hard-redirects /portfolio and /backtest to /profiler, so both show up as API endpoints rather than screens.
  3. Broker data is best-effort and partly credentialed: the Stockbit panel needs STOCKBIT_JWT_TOKEN (or user/password) and shows a degraded message without it.
  4. Accuracy is bounded by third-party sources - an IDX summary endpoint scraped with curl_cffi, yfinance .JK history, and TradingView - so the numbers are cached copies of someone else's feed, not an exchange-grade tick store.
