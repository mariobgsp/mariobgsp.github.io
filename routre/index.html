[ 01 ] WHAT IT IS

In plain words

routre is a small local gateway that sits between your AI apps and AI providers on your own machine. You point a coding agent at http://127.0.0.1:20128 once, and it keeps working while routre shrinks repetitive tool output before it is billed, replays identical requests from a cache, and switches to the next provider if one is busy or down.

It ships as one static Go binary (~10.6 MiB) with no Node, Python, Postgres or Redis, and idles at about 10 MiB RAM.

It is aimed at anyone running OpenAI/Anthropic-compatible CLIs (opencode, Claude Code, Codex, Cursor) who wants lower token bills and less downtime, plus a per-agent token/cost ledger and a loopback-only browser dashboard.

[ 02 ] ARCHITECTURE

How it is put together

  • CLI entrypoint is main.go with one file per command (setup.go, start.go, stop.go, list.go, models.go, bench.go, update.go); bench.go is the gate that fails on any RTK regression below the target.
  • Every request walks a 7-step pipeline in internal/proxy/: detect dialect → RTK compress → cache lookup → tiered route → candidateRunner retry → translate → relay.
  • internal/rtk/ holds 12 heuristic tool_result filters (git-diff, git-log, grep, tree/ls/find dedup, build-output, smart-truncate) — fail-open, never grows a payload, 500 B–10 MiB window.
  • internal/cache/ is an exact-match LRU keyed by SHA-256 of the canonical JSON body after RTK; streaming SSE and non-streaming entries share a key space but never cross.
  • internal/router/ walks tiers in config order (subscription → cheap → free) with per-provider exponential cooldown 2s → 5m; internal/proxy/runner.go adds one transient retry plus one auth-refresh before failover.
  • internal/proxy/dialect/ is the cross-kind SSE state machine (OpenAI ↔ Anthropic ↔ Gemini); internal/usage/ persists the token/cost ledger to ~/.routre/usage.json, and the loopback-only /ui dashboard is served from internal/proxy.

[ 03 ] INSTALL

Set it up

curl -fsSL https://raw.githubusercontent.com/mariobgsp/routre/main/install.sh | sh
routre version
routre setup
routre serve
export OPENAI_BASE_URL=http://127.0.0.1:20128
export ANTHROPIC_BASE_URL=http://127.0.0.1:20128

[ 04 ] QUICKSTART

See it work

  1. routre setup — wizard writes config.json (providers, tiers, models) and routre.env (API keys, 0600) with no shell exports needed.
  2. routre check — validates the config and reports which API keys are set.
  3. routre serve — starts the gateway on 127.0.0.1:20128 in the foreground (routre start --autostart for a daemon at boot).
  4. curl http://127.0.0.1:20128/healthz — returns ok; then run any agent with OPENAI_BASE_URL/ANTHROPIC_BASE_URL pointed at the gateway.
  5. routre list — shows connected providers plus the per-agent token and cost ledger, including rtk and cache savings.
  6. Open http://127.0.0.1:20128/ui in a browser to set keys and edit the full config without touching JSON by hand.

[ 06 ] TRADEOFFS

What it does not do

  1. The ≥90% figure is measured on tool-result tokens only; output tokens are never compressed, so real-session savings depend on how tool-heavy your traffic is.
  2. Token estimates are an approximation (≈4 bytes/token) — a benchmark instrument, not billing-grade; tiktoken integration is listed as planned.
  3. The npm distribution is deprecated: the package prints the curl command and exits, and no release automation remains for it.
  4. Windows self-update is deferred — routre update on Windows prints a re-install hint instead of replacing the running .exe; Windows binaries are still shipped for manual install.
