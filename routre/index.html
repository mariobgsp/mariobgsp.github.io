[ 01 ] WHAT IT IS

In plain words

routre is a small local gateway that sits between your AI apps and AI providers on your own machine. Point a coding agent at http://127.0.0.1:20128 once and it keeps working while routre shrinks repetitive tool output before it is billed, replays identical requests from a cache, and switches to the next provider if one is busy or down.

It ships as one static Go binary (10.9 MiB) with no Node, Python, Postgres or Redis; it idles at about 12.6 MiB RAM, adds ~26 ms p50 on a 1 MiB body, and its bundled catalog lists 509 models.

The shipped RTK level is "routre": the repo's benchmark measures 94.8% aggregate / 93.3% worst-payload tool-token reduction (level: standard measures ~91%).

It is aimed at anyone running OpenAI/Anthropic-compatible CLIs (opencode, Claude Code, Codex, Cursor) who wants lower token bills and less downtime, plus a per-agent token/cost ledger and a loopback-only browser dashboard.

[ 02 ] ARCHITECTURE

How it is put together

  • CLI entrypoint is main.go with one file per command (setup.go, start.go, stop.go, list.go, models.go, bench.go, update.go); bench.go is the gate that fails on any RTK regression below the target.
  • Every request walks a 7-step pipeline in internal/proxy/: detect dialect → RTK compress → cache lookup → tiered route → candidateRunner retry → translate → relay.
  • internal/rtk/ holds 11 heuristic tool_result filters (git-diff, git-log, grep, tree/ls/find dedup, build-output, smart-truncate) — fail-open and never grows a payload. Very large payloads stay bounded: filters score at most a 512 KiB scan window and one request body gets a 150 ms compression budget.
  • internal/cache/ is an exact-match LRU keyed by SHA-256 of the canonical JSON body after RTK; streaming SSE and non-streaming entries share a key space but never cross. An on-disk snapshot keeps the cache warm across restarts instead of starting cold.
  • internal/router/ walks tiers in config order (subscription → cheap → free) with per-provider exponential cooldown 2s → 5m; internal/proxy/runner.go adds one transient retry plus one auth-refresh before failover. Slow upstreams get adaptive, configurable budgets: timeouts.candidate_seconds defaults to 45 s, with one bounded 45 s extension and a 120 s header ceiling.
  • internal/proxy/dialect/ is the cross-kind SSE state machine (OpenAI ↔ Anthropic ↔ Gemini); internal/usage/ persists the token/cost ledger to ~/.routre/usage.json, and the loopback-only /ui dashboard is served from internal/proxy.

[ 03 ] REQUEST PIPELINE

What happens to one request

Seven steps run in order. Choose a cache miss to follow a full upstream round-trip, or a cache hit to see where the reply short-circuits.

  1. The three dialects differ in paths, headers and event shapes. routre normalises the incoming request here so every later step sees one shape.

  2. 11 heuristic filters target diffs, logs, grep hits, file trees and build noise. Compression is fail-open and never grows a payload; very large payloads stop at a 512 KiB scan window or a 150 ms budget.

  3. The key is SHA-256 over the canonical JSON body after RTK. On a hit the saved response is replayed byte-for-byte with no upstream call, so the request jumps straight to the relay.

  4. Tiers are walked in config order and a provider that just failed is held back by an exponential cooldown (2 s to 5 m), so a busy provider is skipped rather than retried forever.

  5. One immediate connection-level retry, one free auth refresh on 401/403, then failover. Each candidate gets an adaptive slice — timeouts.candidate_seconds is 45 s by default, with one bounded 45 s extension while the socket is alive.

  6. A cross-kind SSE state machine converts streaming events on the fly, so an OpenAI-shaped client can talk to an Anthropic provider and vice versa.

  7. On a miss the upstream stream is relayed as it arrives; on a hit the saved stream is replayed. Mid-stream aborts are never cached.

[ 05 ] QUICKSTART

See it work

  1. routre setup — wizard writes config.json (providers, tiers, models) and routre.env (API keys, 0600) with no shell exports needed.
  2. routre check — validates the config and reports which API keys are set.
  3. routre serve — starts the gateway on 127.0.0.1:20128 in the foreground (routre start --autostart for a daemon at boot).
  4. curl http://127.0.0.1:20128/healthz — returns ok; then run any agent with OPENAI_BASE_URL/ANTHROPIC_BASE_URL pointed at the gateway.
  5. routre list — shows connected providers plus the per-agent token and cost ledger, including rtk and cache savings.
  6. Open http://127.0.0.1:20128/ui in a browser to set keys and edit the full config without touching JSON by hand.

[ 08 ] TRADEOFFS

What it does not do

  1. The ≥90% figure is measured on tool-result tokens only; output tokens are never compressed, so real-session savings depend on how tool-heavy your traffic is.
  2. Token estimates are an approximation (≈4 bytes/token) — a benchmark instrument, not billing-grade; tiktoken integration is listed as planned.
  3. The npm distribution is deprecated: the package prints the curl command and exits, and no release automation remains for it.
  4. Windows self-update is deferred — routre update on Windows prints a re-install hint instead of replacing the running .exe; Windows binaries are still shipped for manual install.
