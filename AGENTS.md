# Working rules for this repo

## Branches

- Work on **`develop`**. It is the integration branch and every change lands there first.
- **Do not create feature branches.** No `feat/*`, `fix/*`, worktrees or topic branches — commit straight to `develop`.
- **`main` is the published branch** (GitHub Pages serves from it). Touch it only when the
  owner asks to sync: `git switch main && git merge --ff-only develop && git push origin main`.
- **Sync `develop` and `main` only when asked.** Until then `main` may sit behind `develop`;
  do not "helpfully" fast-forward it after every commit.
- **Exception — automated article publication.** The `articles-sync` workflow is a standing
  owner request: on a green run it commits the *generated articles output* to `develop` and
  fast-forwards `main` from `develop`. It never forces, never creates a branch, and never
  rewrites a file a human wrote. It is the only machine allowed to touch `main`, and it
  runs the sync command above rather than an equivalent of its own — so a fast-forward
  carries pending `develop` commits too, and an article push publishes them. The manual
  command stays how the owner publishes on their own schedule.
- Delete any branch that is neither `main` nor `develop`, local and remote, when you find one.

## Commits

- Conventional commits, imperative subject, lowercase after the type:
  `feat(home): …`, `fix(cert): …`, `content: …`, `chore(repo): …`, `docs: …`.
- One concern per commit. Say what changed and why in the body when the "why" is not obvious.

## Generated files

- `articles/*/index.html`, `articles/index.html`, `sitemap.xml` and the
  `<!-- article:begin -->` … `<!-- article:end -->` region of `index.html` are produced by
  `tools/build-articles.py`. Edit the generator or the article sources, never the output;
  run `python3 tools/build-articles.py` (source: sibling `../articles`, `$ARTICLES_SRC`, or
  `--src`) and check with `--check`. Its image cleanup keeps `assets/articles/og-*.png` on
  purpose.
- The article set is **discovered, not listed**: every root-level `*.md` in the articles
  checkout is an article except `README.md`. Reading position comes from an `Order` row in
  the article's own facts table, which the generated page hides. An article without that row
  is reported and placed last, never dropped, so a forgotten row cannot hide a page.
- The home region owns the article list, its count and the `Updated` date. Keep the prose
  above the marker free of counts. A `/articles/<slug>/` link written by hand anywhere in
  `index.html` is checked against the live article set, so a renamed article fails the build
  instead of 404ing on the site.
- `.github/workflows/articles-sync.yml` regenerates and publishes this output hourly. It runs
  what a human runs, and only ever commits regenerated bytes. `schedule` only runs the copy on
  the default branch, so it stays dormant until this file reaches `main` once; after that the
  fast-forward keeps `main`'s copy current on its own.
